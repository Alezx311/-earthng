## Мета

Гравець відкриває в BeamNG мапу світу, обирає будь-яку точку, камера «опускається»
з висоти до землі, і за ~30 с він їде реальними дорогами з фізикою BeamNG. Світ
догенеровується попереду, позаду вивантажується. Масштаб 1:1, як у MSFS.

**Що «як у MSFS», а що ні.** Беремо схему MSFS (глобус → вибір → спуск → стрімінг
тайлів кількох LOD навколо гравця). Не беремо дані MSFS: фотограмметрія Bing і
кеш MSFS недоступні ліцензійно, а SimConnect не віддає геометрію. Тому джерела
лишаються наші: OSM + DEM + похідні правила Earth2Road. Обіцянки — з картки проєкту:
розташування з даних, висоти/фасади з припущеннями.

## Що BeamNG уже вміє в рантаймі (прочитано в Lua гри, 0.39.4.0.20972)

| Потреба | API в грі | Де видно |
|---|---|---|
| Геометрія з пам'яті без файлів | `createObject('ProceduralMesh')`, `mesh:createMesh({{ {verts, faces, normals, uvs, material} }})`, `setPosition` | `lua/ge/extensions/editor/tech/roadArchitect/roadMesh.lua:347-360` |
| Геометрія з DAE | `createObject('TSStatic')` + `shapeName`, `registerObject` | `core/groundMarkerArrows.lua`, `util/trackBuilder/markers.lua`; KB-нотатка: сирий `.dae` з mod-zip компілюється при завантаженні |
| Перебудова фізичної колізії | `be:reloadCollision()` / `be:reloadCollision(false, true)` | `util/trackBuilder/splineTrack.lua:390`, `core/dynamicProps.lua:95` |
| Рельєф у рантаймі | `TerrainBlock()` + `setTerrFileLvlFolder`, імпорт PNG heightmap | `util/terrainGenerator.lua:170-181` |
| AI-навігація без рівня | `map.loadMap(customMapNodes)`; інакше граф будується з усіх `DecalRoad` | `lua/ge/map.lua:584-587, 2497-2515` |
| Зв'язок із нашим процесом | `BNGWSClient.getOrCreate(url, '')` (WebSocket, subprotocol — рядок) | KB: Minecraft inside BeamNG |
| Тестовий оракул | `-enablemcp` → MCP `127.0.0.1:29292/mcp`: `run_lua`, `load_level`, `screenshot`, `set_position` | KB: Minecraft inside BeamNG |

Наш експортер уже пише навігацію як невидимі `DecalRoad` (`adapters/beamng/beamng_network.py`)
і статичні DAE з hash у назві. Тобто формат даних для BeamNG у нас є; бракує доставки
в рантаймі замість ZIP-рівня.

**Невідомі (кожна — окремий спайк):** скільки триває `reloadCollision` (повна
перебудова чи інкрементальна, що означають аргументи); чи підхоплюється DAE, записаний
у userfolder після старту гри; чи має `ProceduralMesh` колізію для коліс; точність
float32 на кількох кілометрах від початку координат; скільки коштує `map.loadMap`
на тисячах вузлів.

## Архітектура

```
 BeamNG.drive (mod zip earth2road_stream)            Earth2Road stream-server (Python)
 ┌──────────────────────────────────────┐   WS     ┌───────────────────────────────────┐
 │ UI app: мапа світу (MapLibre)        │◄────────►│ запити: pick(lat,lon), pose,      │
 │ ge extension e2r_stream:             │ 127.0.0.1│   heading, speed                  │
 │  • тайл-менеджер (кільця R0/R1/R2)   │          │ планувальник: пріоритет тайлів    │
 │  • spawn/unload TSStatic|ProcMesh    │          │   за напрямком і дорожнім графом  │
 │  • пакетний reloadCollision          │          │ N воркерів: існуючий генератор    │
 │  • DecalRoad/map.loadMap для AI      │          │ frozen store (SQLite за OSM id)   │
 │  • rebase початку координат          │          │ кеш джерел: PBF-регіони + DEM     │
 │  • камера спуску, межа-«туман»       │          │ вихід: DAE/бінарні меші в userdir │
 └──────────────────────────────────────┘          └───────────────────────────────────┘
```

**Рівень-носій.** Порожній рівень `earth2road_void` у mod-zip: небо, світло, вода
на 0 м (або без неї), без TerrainBlock. Все інше приходить тайлами. Рівень один на
всю планету, тому немає перезавантаження рівня між місцями.

**Система координат.** Локальна ENU-проєкція з якорем (regional frame). Тайли
250×250 м з адресою в цьому фреймі. Коли гравець відходить від якоря далі ~4 км,
виконується rebase: усі тайли й транспорт зсуваються на ціле число тайлів (див. S5).
Збережений frozen-стан зберігається в географічних координатах/OSM id, не в
координатах фрейму, тому rebase не змінює даних.

**Кільця LOD.**

| Кільце | Радіус | Вміст | Колізія |
|---|---|---|---|
| R0 | 3×3…5×5 тайлів довкола авто | Повна геометрія roadgen-v2, бордюри, будівлі, DecalRoad для AI | так |
| R1 | до ~1,5 км | Дороги й земля спрощені, будівлі-коробки | ні |
| R2 | до 10–20 км | DEM 30–90 м сіткою + колір landcover, без OSM-деталей | ні |
| горизонт | далі | skybox/туман | ні |

R2 будується за секунди (лише DEM), тому він і є картинкою під час спуску.

**Спуск = бюджет генерації.** Виміряне вікно 250 м — ~25–30 с до готової фізики
(STREAMING.md). Анімація камери 3 км → землі триває стільки ж: спочатку R2, потім R1,
потім R0. Авто спавниться, коли R0-тайл зі стартовою дорогою має колізію. Якщо
генерація повільніша, камера зависає над точкою з прогресом, а не падає в порожнечу.

**Генерація попереду.** На 90 км/год тайл 250 м проїжджається за ~10 с, а один
тайл коштує ~25 с одного ядра. Тому: N воркер-процесів, look-ahead за напрямком
руху та за дорожнім графом (OSM-граф дешевий і відомий наперед, дорога геометрія
— ні). Якщо гравець обганяє генерацію, на межі готової зони стоїть м'який бар'єр
(туман + невидима стіна + повідомлення), а не обрив. Межа офлайн-джерел — так само.

**Чому не перебудова вікон.** STREAMING.md показав: незалежно зібрані вікна реального
OSM розходяться до 1,27 м, бо рішення v2 залежать від далекого контексту. Тому
стрімінг можливий лише як **зростання**: кожен новий тайл читає вже побудовані дороги
й рішення перехресть із frozen store як граничні умови й ніколи не перерішує
готове перехрестя. Це головна алгоритмічна робота й вона не залежить від BeamNG;
її можна розвивати й тестувати в Godot-прототипі паралельно.

**Джерела.** Overpass не годиться для потокового режиму (ліміти, HTTP 429).
Потрібні регіональні PBF (Geofabrik) і DEM-тайли (Copernicus GLO-30), завантажені
наперед для регіону після вибору точки, з наявною офлайн-підготовкою
(`earth2road data prepare`). Для мапи вибору в UI — векторні тайли з провайдера,
що дозволяє такий трафік (не tile.openstreetmap.org напряму).

**Трафік.** У BeamNG — власний AI (`gameplay_traffic`) поверх нашого графа
навігації, як у поточному експорті. SUMO в BeamNG-режимі не потрібен.

## Спайки (вертикальний зріз першим)

Кожен — у порожньому рівні, з оракулом через MCP (`run_lua` + `screenshot`) і
записом чисел. Без S1–S3 решта не має сенсу.

1. **S1 — рантайм-тайл.** Взяти один готовий DAE-тайл з наявного експорту; Lua
   записаного після старту гри тайла в userfolder спавнить `TSStatic`, далі
   `reloadCollision`, авто їде по ньому. Виміряти: чи підхопився файл, час
   спавну, фриз кадру.
2. **S2 — ProceduralMesh.** Той самий тайл через `createMesh` з Lua-таблиць
   (дані через WebSocket). Порівняти з S1: час, пам'ять, чи є колізія.
3. **S3 — ціна колізії.** `reloadCollision` при 1/4/9/25 тайлах; чи залежить від
   загальної кількості трикутників (повна перебудова) чи від доданих. Від цього
   залежить, чи R0 оновлюється пакетами в русі, чи лише на «зупинках».
4. **S4 — AI-граф.** Створити DecalRoad тайла в рантаймі, `map.reset()`/
   `map.loadMap`; трафік їздить. Час на 1/9 тайлів.
5. **S5 — далеко від нуля і rebase.** Їзда на 10 км від початку: тремтіння
   камери/коліс. Зсув усіх об'єктів і авто в русі зі збереженням швидкості.
6. **S6 — вивантаження.** 20 хв їзди по колу зі спавном/видаленням: пам'ять і
   кількість об'єктів стабільні.
7. **S7 — stream-server.** Довгоживучий процес, черга тайлів, frozen store,
   WebSocket-протокол. Почати з даних уже зібраного великого world (без
   генерації в русі), щоб відокремити доставку від генерації.
8. **S8 — UI вибору й спуск.** UI app з мапою → `pick` → R2 → спуск → спавн.

Порядок продукту: S1–S3 → S7 на готовому world (їзда по Біличах тайлами, без
генерації) → S4–S6 → генерація-зростання з frozen store → S8.

- **Працює повністю.** Рендер ідентичний DAE (скриншоти `s1-car-driven.png`), колізія
  справжня (підйом), жодного імпорту COLLADA, жодного кешу на диску.
- **`createMesh` дешевий і передбачуваний:** ≤6 мс на шматок 1500 трикутників,
  ~2,7 мкс/трикутник. Вартість — у Lua: читання + побудова таблиць ~6 мкс/трикутник.
- **Залишкові піки 30–57 мс** не від `createMesh`; імовірно GC LuaJIT або перше використання
  матеріалу (прогони 19: «решта» без нових матеріалів — 29 мс). Не доведено.
- **`reloadCollision` з ProceduralMesh дорожчий:** 25–39 мс проти 3–5 мс у TSStatic на тому ж
  обсязі (у TSStatic спільний кеш мешів). На міських обсягах це може стати фризом — виміряти.
- Холодний ProceduralMesh vs холодний DAE: сумарна робота подібна (~1,1 с на кільце 450 м),
  але proc ділиться на будь-які шматки, а один DAE — ні.

Пастки (BeamNG 0.39.4, GE Lua):
1. **Порядок обходу.** `ProceduralMesh` чекає протилежний до COLLADA. Без розвороту (прогін 05)
   меші невидимі зверху, а одностороння колізія «тримає» авто на місці. `s1.py _wind()`.
2. **`ffi.cast` повертає аргумент без змін**, арифметика вказівників на cdata падає
   (`bad argument #1 to '__add' (invalid C type)`). Робочий шлях: `ffi.new('float[?]')` і
   `ffi.new('uint32_t[?]')` + `ffi.copy` тих самих байтів, індексація словами (усі поля 4 байти).
3. **Площина z=0** в рівні без терену (див. поправку вище).
4. Ім'я `TSStatic` не може збігатися з ім'ям матеріалу (`e2r_pad`) — об'єкт не створюється.

Висновок: основний шлях для холодних місць — бінарні шматки + `ProceduralMesh` з
бюджетом; повторні візити — DAE з кешем `.cdae` або той самий proc. Наступне: причина піків
30–57 мс (профілювання GC), ціна `reloadCollision` на 1–4 км², потім S4 (AI-граф).

- **Прогрів матеріалів прибирає це з часу їзди.** 115 матеріалів району, по трикутнику кожного
  перед камерою: один фриз 2,3 с (холодно) / 0,9 с (приготовані DDS) — це час спуску камери.
  Після нього стрімінг геометрії: середній кадр 16–24 мс, піки 72–127 мс.
- Залишкові піки: перше використання пропсів гри (ліхтар/світлофор — до 87 мс за об'єкт;
  теж можна прогрівати) і `reloadCollision` ~40 мс одним кадром.
- DAE на реальній карті гірший: один тайл блокує кадр на 0,2–0,5 с навіть з `.cdae`.

Висновки: генератор має віддавати **готові DDS** (BC1/BC3/BC7 з мипами) замість PNG; набір
матеріалів району — частина маніфесту регіону й прогрівається до появи авто; пропси гри теж
прогріваються; `reloadCollision` групувати й робити рідко.

## Дані: звідки брати OSM і рельєф для «будь-якої точки»

Питання — онлайн із затримкою/недоступністю серверу чи локальні моди-кеші для кожної країни.
Факти (12.10.2026, HEAD-запити): Geofabrik — Україна 839 МБ, Польща 2,0 ГБ, Німеччина 4,6 ГБ,
Європа 33,6 ГБ; планета 90,8 ГБ. Earth2Road уже має: локальний PBF має пріоритет над Overpass,
`data suggest/download` з явним `--accept-bytes`, незмінні ревізії кешу, `--mode offline`,
рельєф Mapzen з AWS Open Data (статичні файли).

Ключові спостереження:
- **Дані — не вузьке місце за часом.** Генерація вікна 250 м — ~25–30 с CPU; завантаження
  джерел для нього — кілобайти–мегабайти. Затримка мережі ховається за спуском і look-ahead.
  Проблема — **доступність і ліміти**, а не мілісекунди.
- **Overpass не підходить як основне джерело**: публічні сервери мають ліміти (HTTP 429),
  бувають недоступні, а потоковий режим дає багато дрібних запитів від кожного гравця.
- **Свій сервер з обчисленнями не потрібен.** Достатньо статичних файлів за CDN: вони не
  «падають» від навантаження і не мають ціни за запит у тій самій мірі, що API.
- **Не роздавати згенеровану геометрію.** Вона в десятки разів більша за джерела й залежить
  від версії генератора. Роздаємо джерела, генеруємо локально, результат кешуємо локально.

Запропонована схема (джерела в порядку перевірки):

1. **Локальний кеш гравця** — уже згенеровані тайли (frozen store за OSM id), `.cdae`/`.dds`
   кеш гри, сирі джерела. Повторний візит не потребує мережі.
2. **Регіональний офлайн-пакет (необов'язковий)** — «Завантажити Україну для офлайну»:
   ті самі сирі тайли регіону одним архівом (≈ розмір PBF країни + DEM). Для тих, хто хоче
   гарантію без інтернету; не окремий мод на країну, а дані для одного компаньйона.
3. **Статичний архів сирих тайлів OSM на CDN (основний онлайн-шлях).** Раз на тиждень
   планета ріжеться на тайли (напр. z13 ≈ 5×5 км на середніх широтах) зі стратегією
   «повні лінії» (`osmium extract --strategy complete_ways`), кожен — маленький PBF.
   Хостинг — об'єктне сховище без плати за трафік (напр. Cloudflare R2) або один файл з
   HTTP range-запитами. Кожна збірка має дату; регіон у frozen store закріплюється за однією
   датою, щоб сусідні тайли не розходились через правки між знімками.
4. **Рельєф** — уже використовувані статичні тайли AWS Terrain Tiles (або Copernicus GLO-30).
5. **Запасні шляхи з явною згодою**: завантаження країни з Geofabrik (`data download
   --accept-bytes`), Overpass лише для дрібних дозапитів. Без мережі й без кешу — чітка
   помилка «немає даних для цієї точки», ніяких вигаданих доріг.

Архітектурний наслідок: мод BeamNG — тонкий Lua-клієнт; генератор, кеші й завантаження —
у компаньйоні Earth2Road (Python не працює всередині гри). Ліцензія: тайли OSM — похідна база
даних під ODbL; роздавати з атрибуцією й на тих самих умовах.

Не перевірено: розміри й час нарізки тайлів z13 для країни; затримка/надійність CDN;
скільки тайлів джерел потрібно на 1 км² у місті/селі. Це наступний спайк даних (S-data).

- Вікно ImGui: мапа (компаньйон малює її з тайлів OSM з кешем і зеленою зоною покриття),

  прогрів матеріалів (камера на 350 м) → покроковий спавн під час спуску → `reloadCollision`

  109 мс; прогрів — один фриз 0,49 с; їзда: авто на дорозі (z 5,4–6,2, не на площині 0),
  ~72 м за 8 с, найгірший кадр 39 мс.

Пастки прототипу:
1. Ім'я розширення `e2r_world` гра шукає як `lua/ge/extensions/e2r/world.lua`
   (підкреслення = тека).
2. `imguiUtils` не глобальний: `require('ui/imguiUtils')`. Помилка в `onUpdate` до малювання
   вікна давала порожнє вікно, що блимає; логіка тепер у `xpcall`, вікно малюється завжди.
3. `os.replace` на `status.json` падає з WinError 5, поки гра читає файл — повтор із паузою.
4. Перший старт нового профілю прибирає невідомі файли/теки в теці користувача.
5. Телепорт у тому ж кадрі, що й `reloadCollision`, — авто провалюється крізь нові дороги.

Не зроблено: стрімінг під час їзди (лише одна ділянка 500 м на висадку), трафік/AI, дерева,
DDS, мапа на власних тайлах замість tile.openstreetmap.org (dev-заглушка, не для навантаження),
точки поза Києвом (чітка помилка `no_data`).

## Тайли без швів: регіональні рішення + ореол — 2026-10-13

Задача ночі: світ якості roadgen-v2, що генерується на льоту довкола авто, і проїзд Києвом
з півночі на південь (Оболонь → Поділ → Хрещатик → Печерськ → Голосіїв, маршрут 23 км).

**Чому незалежні вікна не сходились (1,27 м) і що з цим зроблено.** Розбір v2 показав, що далекий
контекст входить через небагато входів: `netconvert` по всьому bbox (`--junctions.join`,
`--geometry.remove`, обрізання ребер на межі), штрихи висот (`road_elevation.ground_profiles`:
фільтр до 90 м, падінг ≥ 240 м, висота вузла від «довшого штриха») і рамка (проєкція від bbox,
висоти відносно центру карти). Решта рішень v2 (патчі перехресть, `align_strips`, конфлікти,
тротуари, ґрунт) локальні в межах десятків метрів. Тому:

1. **Регіон** (`earthng/region.py`, раз на 20×20 км): OSM лише доріг і колій регіону → той самий
   `prepare.build` до мережі й висот включно (`context.stop_after = 'elevation'`) →
   `network.net.xml` регіону, `elevation.pkl` (профілі за OSM way id, висоти вузлів), якір і
   `base_height`. Геометрії не будується.
2. **Тайл** (`earthng/tiles.py`, 500×500 м сітки регіону, ореол 80 м): мережа тайла вирізається з
   мережі регіону `netconvert --sumo-net-file … --keep-edges.in-boundary --offset.disable-normalization`
   (через кешовані блоки 2 км: виріз з регіону 23 с, з блока 0,2 с); висоти й рамка — з регіону
   (`context.region` у `prepare.build`); далі звичайний v2 і експорт BeamNG у бінарні шматки.
   Тайл віддає лише об'єкти, чия клітинка експорту 250 м (або власна позиція) лежить у його
   квадраті.

Гачки в ядрі Earth2Road — лише необов'язкові атрибути `context` (`region`, `stop_after`); без них
`prepare.build` працює як раніше.

перевірено `out/scratch/probe.py`, точки за 13–244 м від меж тайлів, тобто не шов). Це черга
для Earth2Road, не для стрімінгу.

Не зроблено / обмеження: тайли без доріг (Дніпро) порожні, без ґрунту й води; ручна їзда
швидше ~35 км/год упирається в генерацію (бар'єр «генерую попереду»); регіон готується
20 хв і лише для Києва-ПнПд; карта вибору досі з tile.openstreetmap.org (dev); трафіку/AI немає.

Пастки:
1. Аркадна коробка BeamNG вмикає задню, коли гальмо тримається на місці, і тоді газ гальмує:
   автопілот, що гальмував перед незавантаженим тайлом, «заклинило» на 1,8 км (route-02). На
   малій швидкості — лише ручник.
2. `test_world.py` закривав компаньйон через `terminate()`, а його процеси-збирачі лишались і
   їли CPU наступного прогону: тепер `taskkill /T`.
3. `netconvert`, що читає `.net.xml`, перераховує форми перехресть: потрібні ті самі
   `--junctions.corner-detail 5 --default.connection.cont-pos 0`, що й у збірці.
4. Тайл без доріг (Дніпро, озера Оболоні): виріз мережі падає з «No edges loaded». Такий тайл
   доставляється порожнім маніфестом (гра вважає його завантаженим), без ґрунту: v2 будує ґрунт
   довкола доріг. Тайл, де немає «звичайної» дороги ≥ 120 м, падав на виборі спавну — з
   `context.region` годиться будь-яка смуга для легковиків (спавн потрібен лише тайлу висадки).
5. Спавн шукається біля `cfg['center']`, а не біля центру рамки: з регіоном це різні точки
   (раніше авто з'являлося за 400 м від точки висадки).
6. **Кадри 1–5 с під час їзди (route-03…06) давав `util_materialHotReload` гри.** Він стежить за
   кожним `*.materials.json` у файловій системі гри і, коли компаньйон доставляв тайл із
   `<i>_<j>.materials.json`, заново розбирав файл і перестворював ~80 наявних матеріалів
   («duplicate material. Overwriting» у `beamng.log`). Перші гіпотези — CPU збирачів і
   `reloadCollision` — виміри спростували: `reloadCollision` 0,02–0,16 с (612 тис. трикутників),
   а ривки лишились і з пониженим пріоритетом, і з 3–5 перебудовами колізії замість десятків.
   Тепер файл тайла — `<i>_<j>.mats.json`, а мод завантажує лише визначення, яких ще не бачив
   (тимчасовий файл `e2r_world/materials_<n>.json`). Route-07: найгірший кадр за 5 хв їзди
   275 мс, середній 7,8 мс. Збирачі все одно на `BELOW_NORMAL` (успадковують і дочірні
   `netconvert`), а до готовності тайла висадки працюють не більше 4.
7. Новий профіль BeamNG показує діалог згоди, доки `onlineFeatures` **і** `telemetry` не
   встановлені (`ui/legal.lua`): тестовий профіль ставить обидва в `disable`.

## Ризики

- `reloadCollision` виявиться повною перебудовою з фризом сотні мс: тоді більші
  тайли рідше, оновлення R0 далеко попереду, або фриз ховається за поворотами.
- Пропускна здатність генератора: потрібен багатоядерний CPU; на швидкостях
  трасу генерація не встигне — бар'єр і обмеження реальні.
- Frozen-growth для roadgen-v2 — нерозв'язана задача; legacy-генератор може
  бути першим кандидатом для стрімінгу, якщо він стабільніший до контексту.
- Оновлення BeamNG змінюють внутрішній Lua: тримати точну версію в цьому файлі.
- Тільки одиночна гра; мод вимикати перед BeamMP.
